# B2B 规划与转化

用于新站访谈、关键词研究、行业对标、页面规划、内容组织和转化审查。目标是让网站按买家的实际搜索与采购判断构建，而不是把企业图册直接搬到网上。

## 1. 最少确认的信息

每轮只问会改变页面、询盘或部署的少量问题；能从资料和仓库查到的不要重复问。

这是逐阶段清单，不是开场问卷。第一轮以产品、买家和市场为主；客户已有资料就用，未整理时先记录待补，用标记预览完成样板。不要先问账号/Key 或强求整套公司材料。样式确认后，按 [客户资料与素材交接](content-and-asset-handoff.md) 主动邀请上传。

- 产品或工业服务是什么？核心利润产品是什么？
- 采购者是进口商、经销商、品牌方、工程师还是采购经理？
- 目标国家、语言和主要搜索习惯是什么？
- 什么询盘才算合格，需要收集产品、规格、数量、国家、时间或图纸中的哪些字段？
- 有哪些真实可公开的工厂、认证、检测、案例、交期和能力证据？
- 首版需要哪些页面，哪些明确不做？
- 内容由 Agent 改代码部署，还是用户真正需要 CMS？

## 2. 用搜索数据决定页面

不要从老板认为“应该展示什么”开始。先完成：

```text
产品名称与同义词
→ 扩展真实搜索词
→ 根据实际业务排除不相关意图（如不经营的租赁、求职、培训、娱乐）
→ 按修饰词、总搜索量、语义和采购意图聚合
→ 形成产品分类、应用、参数与采购页面
```

同义词不应机械合并。如果两个表达拥有不同搜索结果、不同买家用法或都存在显著需求，可以建立不同的分类入口；页面内容必须有实际差异，避免只换词的重复页。

没有关键词数据时先输出“待验证的分类假设”，不伪称数据驱动结论。词频是出现次数，搜索量是搜索需求估计，两者不能混写；参考站排名或低 DR 也不能证明它没有投入成本、没有外链或实际询盘很多。

分类常见维度：

- 产品名称和同义词。
- 尺寸、重量、功率、材料、规格或吨位。
- 驱动、技术或结构。
- 应用行业、工况和问题。
- 采购意图：manufacturer、supplier、price、for sale、custom、OEM 等。
- 国家和供应来源词，但必须评估品牌定位与流量取舍。

金句：

> 网站不是老板想展示什么就做什么，而是客户实际搜索什么、数据指向什么，就优先做什么。

## 3. 对标选择

大型行业龙头可以参考视觉和品牌表达，但新站的信息架构优先参考“够得着”的异常样本：

- 产品词和采购意图词带来的流量占比高。
- 外链、品牌和历史基础不强，仍有具体采购词排名。
- 页面分类能与实际搜索修饰词对应。
- 有清楚的产品、参数、证据和询盘路径。

不要只看总流量，也不要把品牌词流量当作新站可复制的自然获客能力。对标交付写成：

| 对标 | 可借鉴 | 不可复制 | 自有实现 |
|---|---|---|---|
| 网站 A | 视觉风格、摄影比例 | 品牌、外链、客户资产 | 使用自己的证据与获客页面 |
| 网站 B | 分类、长尾页面、CTA | 文案、Logo、专有素材 | 从自身关键词和产品数据生成 |

分别标注“获客参考”和“视觉参考”，允许来自不同网站。获客参考决定做哪些页面和优先展示哪些采购信息；视觉参考决定如何排版和使用素材。不能仅凭漂亮截图选择搜索策略，也不能因为某站排名好就复制其全部视觉。视觉决策执行 [前端设计系统](frontend-design-system.md)。

## 4. Route matrix

每条路由在编码前登记：

| 字段 | 要回答的问题 |
|---|---|
| route | 唯一 URL 是什么？ |
| language/market | 服务哪个语言与市场？ |
| audience | 谁会搜索并访问？ |
| query cluster | 承接哪组词和意图？ |
| job | 买家要完成什么判断？ |
| template | 首页、分类、详情、应用、文章或联系？ |
| primary CTA | 唯一主动作是什么？ |
| content source | 哪个本地数据/Markdown 文件是唯一真源？ |
| evidence | 哪些声明有可核验来源？ |
| SEO | title、description、canonical、hreflang、JSON-LD 从哪里生成？ |
| empty/error | 内容缺失时隐藏、noindex 还是 404？ |

## 5. 首版页面闭环

按真实业务删减，常见首版为：

- Home：定位、对象、差异、证据与主 CTA。
- Products：按搜索和选型方式筛选类别。
- Product detail：适用性、参数、选项、质量、交付、FAQ 与 RFQ。
- Applications：按行业或工况承接需求。
- About/Factory：降低供应、质量和沟通风险。
- Resources：只有具备真实内容计划时才建设。
- Contact/RFQ：收集足够但不过度的合格询盘信息。
- Thank you：仅在询盘成功入库后进入，确认提交结果、说明下一步并承接广告转化追踪；不作为 SEO 页面收录。

默认样板为首页、一个分类页和一个详情页；服务型业务或关键解决方案结构不同，可说明理由后调整/补充代表页。使用正式静态生成器，素材不足可用明确标记的预览；视觉确认后主动补客户真实内容并扩展，正式发布前再验证产品事实和素材。

每个样板要回答不同的买家问题，而非同一个模板换标题：

| 页面 | 买家需要判断 | 视觉与内容优先级示例 |
|---|---|---|
| 首页 | 你能不能服务我，是否值得继续了解？ | 清楚定位 → 产品/能力入口 → 真实证据 → 主动作 |
| 分类页 | 哪种产品符合我的条件？ | 分类说明 → 关键规格/适配/用途 → 可比较的产品 → 详情或询盘 |
| 详情页 | 这个型号是否适合，如何采购？ | 真实图片 → 关键参数与限制 → 证据/选项/交付条件 → 带产品上下文的 RFQ |

这是按任务组织信息的示例，不是固定视觉模板。机械可重视吨位与工况，配件可重视型号适配，OEM 可重视工艺、材料与定制条件；未确认事实不能为了完成页面而编造。

## 6. 区块存在门槛

每个区块至少完成一项：

1. 帮助买家判断是否匹配。
2. 降低质量、交付、合规或沟通风险。
3. 提供可核验证据。
4. 推进询盘动作。

四项都不满足就删除。不要使用没有证据的数字墙、假客户 Logo、空洞优势图标、重复 CTA 和只为展示设计技巧的模块。

## 7. 内容真实与上线门禁

强声明记录 `claim / owner / source / verifiedAt / scope / publishState`。未核验内容标记 placeholder，并保持 noindex。上线前阻止：

- 假客户、假评价和未授权 Logo。
- 无来源认证、产能、交期、出口国家和效果数字。
- 信息图片缺失有效 alt、模板地址、假邮箱和无法使用的联系方式；纯装饰图片应使用空 alt，不误判为缺陷。
- 未经授权复制对标站文案、图片、Logo 或品牌专有表达，或将他人素材/AI 示意冒充客户真实产品与企业证据。
