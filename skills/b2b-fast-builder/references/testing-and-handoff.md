# 测试与交接

用于静态站构建、上线、性能、询盘闭环、媒体和后续 Agent 更新的验收。

## 1. 代码与构建

遵循项目自己的包管理器和命令，并提供单一 `quality` 入口，严格按以下顺序运行：

- 类型检查，零 `as any`。
- lint 与相关单元测试。
- production build。
- 静态输出验证脚本，且必须显式传入 route manifest。
- 构建目录文件数、单文件大小和意外大资源检查。

如果某个命令不存在，先读取项目 manifest 和规则，不凭名称安装替代工具。新增测试工具只在实现任务需要且属于用户范围时进行。

任一环节失败立即终止；不得用 `|| true`、忽略 lint warning、跳过 route manifest 或先部署后补测。Cloudflare Pages 的 Build command 使用同一 `quality` 入口。

## 2. 静态 SEO

对 route manifest 的每条可索引路由验证：

- 对应独立 HTML，HTTP 200。
- 网络响应源代码包含主要标题、正文、参数和内部链接。
- title、description、H1、canonical、lang 存在且与页面一致。
- hreflang 对应页存在并双向匹配。
- JSON-LD 可解析且没有模板假数据。
- sitemap 只含规范、可索引 URL。
- robots 不误封 CSS、JS、图片和正式页面。
- 未知路由返回 404，不是 soft 404。
- 内部链接没有断链、hash route 或错误 host。

关闭 JavaScript 后页面仍能完成阅读和导航；交互增强失效不应让核心内容消失。

## 3. 视觉、响应式与可访问性

至少检查 360/390px 手机、平板、常见笔记本和大屏：

- 无横向溢出，表格有移动端策略。
- Header、菜单、筛选和表单可用键盘操作。
- focus-visible、label、错误提示、landmark 和标题层级正确。
- CTA 触控面积、颜色对比和文字换行可用。
- 图片有 width/height、适当裁切和 alt；首屏只优先加载必要媒体。
- 尊重减少动态偏好，动画不阻塞阅读和询盘。

视觉检查必须使用真实浏览器和真实内容；只跑 build 不能写成视觉通过。

### 截图与定点修改闭环

1. 读取项目 `DESIGN.md`、当前请求和已批准范围。新站覆盖代表性首页、分类、详情；局部修改覆盖受影响页，共享模板修改再抽查使用该模板的页面。
2. 完成 production build，启动实际静态产物的预览，直接打开和刷新深层网址。使用项目已有浏览器工具；只有 SPA 开发预览时不能把它当作最终验收。
3. 截取桌面与手机的首屏及关键操作区域；全页截图适合检查节奏，但不能替代放大检查、键盘和实际操作。记录 URL、viewport、构建版本、时间及截图路径。
4. 先修最影响买家理解或操作的问题：看不出卖什么、图片失真/裁错、参数难比较、CTA 被遮挡、表单难完成。审美细节与阻塞操作问题分开。
5. 有批注功能就使用现成工具；没有时接受截图圈选或自然语言，不声称已内置批注编辑器。将反馈归为“网址/区域 → 问题 → 期望结果 → 局部/模板/全站范围”，只追问会改变范围的信息。
6. 修改真源，重建、复截图并检查原问题及相邻影响，记录已解决、待确认、未验证项。用户确认后更新 `DESIGN.md`；不能用 Agent 自评分冒充用户批准。

可从 [视觉检查记录模板](../assets/visual-review.example.md) 生成项目记录，或复用已有 QA 文档。截图默认保存在本地项目，不自动上传含业务资料的截图到第三方服务。

默认一轮自查后交付样板；为本轮修复做复查，优先关闭关键缺陷。纯审美分歧持续时展示取舍让用户决定，不无限循环或全站重做。没有浏览器时可以完成代码与静态验证，但明确视觉未验证，安排用户回读或后续工具验证，不伪造截图/通过结论。

### 长内容、小语种与失败状态

- 使用真实长产品名、参数、单位和询盘内容，不只测短占位文字；不能靠截断隐藏关键采购规格。
- 按实际目标语言检查字体覆盖、德语等长词和 RTL 布局；翻译页保留正确语言与独立 URL，不只替换导航标签。
- 检查图片缺失、空列表和不可用素材的处理，不生成破图或假产品；公开发布不能残留测试内容。
- 检查键盘焦点、可见 label、正确按钮/链接、错误定位和提交等待状态；异步失败保留输入，聊天/固定按钮不遮挡表单。
- 产品目录保留初始 HTML 与可抓取链接/分页；不能因通用列表虚拟化建议只留下空壳。

### 日常局部更新

| 请求 | 优先修改真源 | 至少复核 |
|---|---|---|
| 换一张产品图 | 对应媒体记录/实体引用 | 使用它的页面、裁切与尺寸，保留其他产品和旧版本 |
| 改文案或参数 | 对应业务实体 | 可见内容及由它派生的 metadata/结构化数据，无关 URL 不变 |
| 增加产品或语言页 | 内容模型与 route resolver | 新页面完整 HTML、导航、canonical、sitemap、适用时 hreflang |
| 改某个区域样式 | 对应组件或局部变体 | 目标区域与相邻布局，不扩展成全站重设计 |
| 改全站字体/主色 | 共享 Token 与设计记录 | 各代表模板、目标语言、对比度、换行与关键操作 |

先读数据、组件调用关系和已有 diff，再确定影响范围；信息明确时直接实施，不要求用户重新填全部建站说明。完整执行质量闸门，视觉复核按影响抽样；发布需在已授权范围内。交接列出修改内容、影响页面和回滚位置，不直接修补 `dist`。

## 4. 询盘闭环

至少验证：

1. 正常提交只创建一条 D1 记录。
2. 重复 `submission_key` 不重复入库和发信。
3. 错误 Turnstile、空字段、超长字段、非法邮箱和错误 origin 被拒绝。
4. Resend 成功后保存发送 ID 和 `sent`。
5. 模拟邮件失败后，D1 仍保留询盘并标记 `failed`。
6. 补发使用同一幂等键并最终更新状态。
7. 表单失败保留用户输入并提供可恢复提示。
8. D1 控制台、CLI 或交接工具能查询全部询盘，而不是只看邮箱。
9. 日志、错误页和普通内容导出不泄露询盘 PII。
10. 只有 D1 写入成功才跳转 `/thank-you/`；校验失败和数据库失败都留在表单页。
11. Resend 失败但 D1 已保存时，感谢页正常显示，后台可查到 `failed` 并补发。
12. 感谢页为 `noindex` 且不在 sitemap；直接访问、刷新和浏览器前进后退不会重复触发转化。
13. 转化事件携带唯一询盘 ID 进行去重，不携带姓名、邮箱、电话或留言。

启用 Tidio 时另外验证：

1. 每个目标静态 HTML 都且只包含一个客户 Public Key 对应的 `code.tidio.co` loader；非目标页面不包含。
2. 全新匿名窗口的桌面和手机端能看到 widget，且不遮挡主 CTA、表单和同意控件。
3. 发送带唯一前缀的测试消息，由客户在自己的 Tidio Inbox 回读；同时检查在线、离线 ticket、Operating Hours 和通知设置。
4. CSP 控制台无阻断，隐私政策和必要同意已上线。
5. 阻止 Tidio 请求后，站内 RFQ 仍能完成 D1 入库、Resend 通知和感谢页跳转。
6. PageSpeed/Lighthouse 使用 Tidio 已启用的正式页面重新测试。

测试记录使用显式前缀；可以安全删除时再清理。生产真实询盘不得拿来做破坏性测试。

## 5. 媒体模式

### local

- 所有引用文件存在于构建产物。
- 没有超出当前 Pages 限制的单文件。
- 图片已压缩，列表页没有加载原始大图。
- 部署后静态 URL 返回正确 content-type 和缓存头。

### r2

- Bucket、客户归属、对象前缀和自定义域名有记录。
- 生产页面不引用 `r2.dev`、临时签名 URL 或本地路径。
- 上传后回读对象或 URL，不能只看命令退出码。
- 缓存策略与版本 key 一致；替换资源能回滚。
- R2 失败不会阻止已有静态页面继续展示旧资源。

## 6. 性能与“满分”声明

测试首页、代表性分类页和产品详情页；移动端和桌面端分开记录。检查真实用户所需的：

- LCP、CLS、INP 和资源瀑布。
- 首屏图片尺寸、字体、第三方脚本和 JavaScript 体积。
- 缓存、压缩、响应码和重定向。

PageSpeed/Lighthouse 四项 100 只有在正式 URL 的实际报告达到时才可展示，并记录：

- 页面 URL。
- 测试日期与时间。
- 移动端或桌面端。
- 工具与运行口径。

分数会波动，不能用一张历史截图承诺所有页面永久满分，也不能用性能分数替代 SEO 和询盘测试。

## 7. 生产 smoke 与回滚

部署后从匿名环境验证：

- 主域名、HTTPS、canonical host 和重定向。
- 首页、分类、详情、联系、robots、sitemap 和 404。
- 一条真实测试询盘的 D1、邮件、感谢页跳转与转化事件闭环。
- local/R2 图片和下载文件。
- Google 可见的源 HTML。

记录上一个可用部署和恢复方式。域名切换、DNS 删除、数据库删除、Bucket 清空和生产内容覆盖属于破坏性操作，必须有精确目标与明确授权。

## 8. 交接清单

- 接入进度、客户需要做的下一步、已安装工具的官方来源/版本；注册完成与服务真正可用分开记录，不附凭据或授权链接。
- 用客户能懂的话交接三处入口：询盘通知的邮箱、D1 备份查询的实际入口、启用聊天时的 Tidio Inbox；不把无 CMS 项目描述成自带管理后台。
- 业务 brief、route matrix 和页面模板。
- `DESIGN.md`、素材来源与解析方式、批准范围、截图/问题记录和局部更新方法。
- 内容真源路径、类型/schema 和生成命令。
- 媒体模式、图片处理与资源更新命令。
- Cloudflare 项目、D1、可选 R2 的资源名称，不包含 Secret。
- 环境变量名称及由谁管理。
- 构建、预览、部署、回滚和域名流程。
- 询盘查询、失败补发和每日检查方法。
- 感谢页、GTM/广告事件、唯一询盘 ID 去重和验证方法。
- 自动测试、浏览器、性能与生产 smoke 证据。
- 已实现、已测试、仅设计、未实施和已知风险分别列出。
