# 客户资料与素材交接

用于先出样板、样式确认后补真实内容的极速建站流程。默认不要求客户提前整理全部资料，也不把图片来源不明或 AI 生成的商品当成客户实物发布。视觉细则见 [前端设计系统](frontend-design-system.md)，账号按 [主动引导上线](guided-launch.md) 到需要时再配置。

## 1. 分开两次确认

| 阶段 | Agent 主动做什么 | 此时不要求什么 |
|---|---|---|
| 开始设计 | 读已有资料，只确认产品、买家、市场与必要风格偏好；准备有出处的预览素材 | 完整图册、注册服务、密钥 |
| 样板评审 | 展示首页/分类/详情的实际静态产物，标明预览素材；根据批注改样式 | 把样式通过当成事实或上线批准 |
| 样式通过 | 立即邀请客户上传自己的公司和产品资料，整理并分批替换 | 客户逐个字段填写技术模板 |
| 内容复核 | 请客户核对型号、参数、图片、联系方式和公开范围；用真实内容再查页面 | 用 Agent 猜测补齐缺失事实 |
| 接入/上线 | 用到哪个服务就接哪个；内容和实际询盘都验证后交付 | 带假资料上线，或把注册成功当成业务可用 |

客户主动提前给的资料立即用；只改已有站局部时复用内容，不重走全套收集。用户明确要求提前部署预览/测试时可在授权范围内接入必要服务，但说明这是预览，不提前索要无关账号。

## 2. 前期如何准备图片

顺序：已有客户图片 → 客户允许使用的自有店铺/供应商素材 → 使用范围清楚的实物摄影 → 当前可用工具生成的产品示意图。可搜索 Google、Alibaba、行业网站找具体产品与摄影参考；不要只给客户空框、通用图标或 SVG 画的机器。

- 搜索时匹配实际产品类别、外观、用途和预期视角，先查看图片本身与来源页，不凭文件名匹配型号。
- **能搜到不等于能发布。** Alibaba/Google 是找图入口，不是授权证明。客户自有店铺也要确认素材是否自有/获准使用；外站产品图使用权不明时只记录参考链接，不下载进网站资源包、不盗链公开展示。
- 若宿主有可用 AI 生图工具，按该工具规范主动准备所需图，不要求客户先去注册新的生图服务。没有工具或需要额外付费时如实说明，改用可使用的摄影素材；不声称已生成。
- AI 图仅用于明确标记的设计示意，不能冒充客户真实 SKU、厂房、员工、认证或客户案例。真实产品改图不得擅自改变结构、商标、附件或参数。正式产品图仍需客户提供或确认与实物一致的获准素材。
- 产品主图优先具体的实物照片或写实示意图，使用适合网页的栅格图片。SVG 可用于 Logo、图标、技术示意，不能拿示意图替代产品摄影；把 SVG 转成 PNG 也不算解决了素材问题。
- 预览清楚标明“设计预览，部分图片/资料待替换”，不编造样本参数和商业证据。预览默认本地或受控访问；若提供在线预览须经授权并 noindex。noindex 不是访问控制，也不能弥补使用权缺失。

## 3. 样式确认后，主动邀请上传

此时不要跳去注册账号。先说：

> 样式已经确定了，接下来把它换成你公司的真实网站。你手头的公司介绍、产品图册、产品照片和参数表可以直接发来，PDF、表格、图片或压缩包都可以，不用重新整理。我先帮你归类，有缺的再单独问你。图片如果在你自己的店铺，也可以发链接，并告诉我哪些可以使用。

按现有资料分批处理；下面是 Agent 的内部清单，不一次要求客户全部填写：

- **公司**：中英文名称、Logo、可公开介绍、联系方式；需要展示时再补真实厂房/团队/检测图片。
- **产品**：型号或产品名、分类、对应图片、参数、选项和适用场景；MOQ、交期、价格等仅在业务需要且已确认时公开。
- **可信证据**：实际具备的认证、检测、案例和服务说明。没有就省略相关区块，不制造“实力数字”。

只要可公开的必要资料，不索取身份证、客户私密合同或账号凭据。遵守宿主上传能力与文件大小限制；不支持附件时提供当前可用的文件夹/资料链接方式，不虚构上传框或 CMS。

## 4. Agent 整理并替换

1. 保留原文件与来源，提取文字、表格和图片到项目内容真源；不要覆盖客户唯一原件或默认提交原始压缩包到公开 Git。
2. 建立“产品 ID → 型号/参数 → 图片 ID → 页面”映射。图片无法确定属于哪个型号时，只把待确认的几张图与产品名发给客户核对，不根据相似外观猜测。
3. 在素材清单记录来源、使用依据、预览/正式状态、客户批准及替换目标，参考 [素材模板](../assets/media-manifest.example.yaml)。私有证据保存在受控位置，公开清单不泄露客户敏感资料。
4. 用同一逻辑 ID 更新内容与图片引用，生成压缩/响应式版本、准确 alt；同步受影响页面正文、标题、结构化数据和下载资料，避免“图片换了、参数还是样例”。
5. 回传简短进度：“已替换哪些、还缺哪些、哪些可先不展示”。缺资料不停止无关布局工作；核心产品无真实资料时不能声称正式站完成，可与客户确认缩减首版范围。
6. 真素材全部替换后，重看首页/分类/详情的桌面与手机效果，请客户确认业务事实和公开范围。只有样式确认记录不能放行内容。

## 5. 正式发布前的内容检查

- 实际发布的产品与公司事实已确认，核心产品图与型号匹配，有使用依据；AI 设计示意、样例公司、示例联系信息不残留。
- 装饰性或场景辅助 AI 图可按用户选择保留，但不得冒充产品实拍或企业证据；必要时标注示意。
- 可选证据缺失时移除区块；不把假素材加 noindex 就当成可正式交付。预览内容留在预览环境，不混入正式构建。
- 替换图片后复核裁切、清晰度、性能、alt、跨页引用与 local/R2 URL；已确认样式不因内容替换擅自全站重做。
- 在 `DESIGN.md` / 项目 QA 记录样式批准、内容批准与遗留项；模板中的布尔值不是自动验证结果，必须有真实检查记录。
